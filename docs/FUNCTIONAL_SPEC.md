# 둘이, 일본 — 개편 구현 계약

개정: 2026-10-06 · 여행 데이터는 TRIP_PLAN 2026-10-06-r3, 기능·디자인은 SENKYO_RENEWAL_PLAN 기준.
이 문서는 구형 기능 명세를 대체한다. 지출/정산, 계획 편집, 후보 식당 관리의 이전 요구는 폐기한다.

## 계정과 권한

사전 생성한 두 사용자만 아이디/비밀번호로 로그인한다. 회원가입·외부 초대·관리자 계정 생성 UI 없음.
Supabase Auth 내부 이메일은 UI에 노출하지 않는다. 로그인 실패 시 계정 존재를 구별하지 않는다.
EDITOR/OWNER는 예약자료, 준비물, 할 일, 쇼핑, 긴급정보, 메모를 수정한다. VIEWER는 조회만 가능하다.
모든 자료는 여행 멤버에게만 공개한다. 계획 테이블은 두 계정 모두 SELECT만 가능하고 순서 변경 RPC도 실행할 수 없다.

## 네비게이션과 오늘

오늘 / 일정 / 지도 / 준비 / 더보기의 다섯 탭. 장소 관리 탭은 제거한다.
더보기는 예약자료, 쇼핑, 긴급정보, 메모/회고, 보관 자료, 여행정보, 설정이다.
오늘은 일본 현지 날짜로 현재/다음 일정 하나를 강조하고 자료/식당/지도 행동을 제공한다.
출발 전에는 D-day와 여행 전 미완료 목록을 먼저 표시한다. 여행 일정은 미리보기라고 명시한다.
여행 후에는 종료 안내를 표시한다. 선택 날짜가 실제 오늘이 아니면 오늘 일정으로 오인시키지 않는다.
미정 시각인 요시노야 식사는 현재/다음 계산에서 제외하고 계획의 확인 필요 사항으로 보존한다.
오늘 숙소, 이후 일정, 당일 준비물/할 일을 표시한다. 지출/정산/가짜 날씨 요약은 없음.

## 읽기 전용 일정과 식당

6일 시간순 타임라인. 계획 시간·근사 표현·일정 순서·지점명을 문서 그대로 보존한다.
FLIGHT/TRAIN/TRANSIT/HOTEL/ATTRACTION/MEAL/SHOPPING/WALK/FREE_TIME/OTHER로 표시하며 BUS/SHUTTLE은 TRANSIT+transport_type으로 매핑한다.
식사 상세는 고정 식당의 복수 연결을 표시 순서대로 지원한다. 현재 각 지정 식사는 1곳만 있다.
식당 음식 종류·설명은 계획서에 명시된 내용만 사용한다. 알려지지 않은 장소/좌표/사진/영업시간을 만들지 않는다.
코메다·요시노야·돈키호테의 지점은 미정 상태다. 특정 장소 없는 간단식에 지도 버튼을 만들지 않는다.
계획 편집·일정 추가/삭제/정렬·장소 검색/등록/연결·식당 후보 변경/선택 저장은 없음.
지도 추천으로 항공·열차·셔틀 시간을 바꾸지 않는다. 계획 시간 고정과 예약 완료는 별개다.

## 예약자료

reservations → reservation_schedule_items → reservation_attachments를 유지한다.
하나의 예약은 여러 일정, 하나의 일정은 여러 예약을 참조한다. 자료를 복제하지 않는다.
이동 일정에서 자료 보기, 기존 자료 연결, 비예약 OTHER 자료묶음 생성을 지원한다.
자료 생성/일정 연결은 한 DB transaction으로 처리한다. OTHER material_only는 예약 완료로 표시하지 않는다.
예약번호·예약자·사이트/확인 URL·편명·차량·좌석·연락처·안내 메모를 편집하고 예약번호를 복사한다.
텍스트만/파일만/혼합 첨부를 지원한다. 제목·설명·텍스트·파일 종류/크기·보기/다운로드 제공.
PDF/PNG/JPEG/WEBP 10MB, 파일 서명+MIME 검사, 텍스트 10,000자. private Storage, 60초 signed URL 재발급.
업로드 성공 후 DB 실패 시 파일 정리를 시도한다. 실패를 성공으로 표시하지 않고 재시도할 수 있다.
첨부를 삭제할 때 사용자 확인을 받고 실패를 지속 표시한다. 갱신되는 QR은 사업자 앱 안내를 유지한다.

## 준비물과 할 일

준비물은 물건/자료, 할 일은 행동. 각 일정에서 작성/수정/삭제/완료 체크를 지원한다.
TRIP/DATE/SCHEDULE 범위와 PRE_TRIP 할 일을 구별한다. PRE_TRIP은 매일 반복 집계하지 않는다.
공통 준비물은 SHARED 또는 개인 USER_A/USER_B 정의로 분리하고 담당자 실제 이름을 표시한다.
checked는 짐 싸기/단회 준비 완료; repeat_daily의 당일 휴대는 packing_checks로 별도 저장한다.
(항목 ID, 날짜, 담당자) 유일성과 같은 여행 FK를 검사한다. 이름이 같다는 이유로 항목을 합치지 않는다.
공통 준비물은 packing_schedule_items로 여러 일정에 연결하고 당일 한 번만 집계한다.
기존 날짜별 항목은 보존한다. 폐기 일정·옛 숙소·폐기 비용/후보 관련 seed 항목은 보관 영역에서 확인한다.

## 당일 전체보기

준비물 전체/체크리스트 전체는 화면 전환 없이 같은 날짜 팝업의 해당 영역을 연다.
공통/날짜 항목 다음에 시간순 일정별 그룹, 담당자/관련 일정 표시, 전체/미완료 필터, 완료/전체 수.
팝업을 연 동안 체크 항목을 즉시 제거/재정렬하지 않는다. 완료 모양과 합계는 갱신한다.
체크 결과는 오늘·상세·준비 화면에 공유하고 실패 시 복구한다. Realtime와 주기적 재조회로 두 계정 상태를 동기화한다.
닫기/ESC/배경 클릭, native dialog 포커스 고정, 호출 버튼 포커스 복귀, 배경 스크롤 잠금, 내부 스크롤.

## 지도

기본은 계획서 장소 검색 Google Maps URLs(api=1). 검증된 공유 링크 또는 Place ID가 있으면 사용한다.
링크를 Places 상세·사진 로딩 성공에 묶지 않는다. Place ID/좌표는 확인 전 null.
날짜별 내장 지도는 보조 기능; 키 없음, 스크립트 로드 실패, 인증 실패, 미연결, 부분 좌표 실패, 장소 없음 구분.
장소 목록과 외부 링크는 API 장애 때도 남는다. 운영 지도 문제는 실제 키/referrer/API/결제 설정 확인이 별도로 필요하다.
/api/places는 필요한 상세 조회를 유지하되 자유 검색 q는 제공하지 않는다. 인증 실패를 Google 오류와 구별한다.

## 유지 기능과 데이터

쇼핑목록, 구매 상태, 긴급 전화/링크, 메모/회고를 유지한다. 계획의 검증된 참고 금액은 읽기 전용이고 지출 집계는 제거한다.
비용 테이블/후보 테이블은 이번 migration에서 삭제하지 않으며 앱 조회/쓰기에서 제외한다.
안정 plan_key와 기존 UUID 매핑을 사용한다. 계획 소유 필드만 갱신하고 개인 예약·첨부·메모·완료는 보존한다.
변경 전 snapshot, dry-run 영향 조회, 보관 처리, transaction, idempotency와 비파괴 롤백 절차를 제공한다.
새 호텔에 옛 호텔 예약을 자동 이관하지 않는다. 오늘/일정/지도/준비는 동일 활성 계획을 사용한다.

## 오프라인·시간·디자인

Asia/Tokyo, date-only, timezone-aware datetime. 오프라인은 로그인했던 같은 탭의 sessionStorage 조회만 지원한다.
인증 페이지/API/첨부는 SW에 캐시하지 않고 로그아웃 시 snapshot을 지운다. 완전한 오프라인 첨부는 범위 밖이다.
화면 전체에 회백색/흰 카드/딥그린 및 작은 겨울 배지, 로컬 Pretendard와 시스템 대체 글꼴 적용.
색상만으로 상태 구분 금지, 44px 터치 영역, 키보드 포커스, reduced-motion, 320~1280px 반응형, 긴 예약번호/지점명 지원.
운영 DB 적용/삭제·Vercel 배포는 수행하지 않는다. lint/typecheck/test/build 및 영향 화면을 검증하고 실행 결과만 기록한다.
